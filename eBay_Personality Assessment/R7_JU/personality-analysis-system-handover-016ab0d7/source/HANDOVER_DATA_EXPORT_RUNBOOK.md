# 資料庫、備份與物件儲存交接手冊

## 先確認資料範圍

本系統資料庫包含受測者個人資料與測驗答案。正式資料匯出屬於敏感個資處理，不能在沒有確認法規、保存期限、接任方責任與加密傳輸方式的情況下直接交付。

一般程式碼交接包只包含 schema、migration 與資料操作說明，不包含 production data dump。若確實需要交付資料，請由專案擁有人在平台原生備份／匯出功能執行，並記錄備份編號、時間、加密方式與接收人。

## 必須交接的資料結構

目前主要資料表如下：

| 資料表 | 內容 | 敏感程度 |
|---|---|---|
| `users` | OAuth 使用者、角色、啟用狀態 | 高 |
| `site_settings` | 品牌名稱、照片 URL/key、浮水印設定 | 中 |
| `submissions` | 受測者基本資料、PART 2 分數、DISC 答案 | 極高 |
| `admin_invitations` | 管理員邀請與狀態 | 高 |
| `deletion_requests` | 個資刪除申請 | 極高 |
| `admin_audit_logs` | 操作者、路由、異動與 API 錯誤紀錄 | 高 |

資料表結構以 `drizzle/schema.ts` 為準，版本演進以 `drizzle/*.sql` migration 為準。交接者應先在測試資料庫恢復 migration，再對照 schema。

## 建議備份流程

1. 在資料庫供應商或 WebDev 管理介面建立加密備份。
2. 確認備份包含 schema、indexes、資料、時區與字元集設定。
3. 在隔離的測試資料庫恢復備份，不要直接覆蓋 production。
4. 執行 `pnpm check`、`pnpm test -- --run`，並以測試環境完成登入、問卷送出、結果查詢與品牌讀取。
5. 將備份檔用獨立密碼加密，密碼透過不同通道傳遞。
6. 新工程師確認可恢復後，再刪除臨時副本並撤銷舊存取權。

## 資料交付前檢查

正式交付前，確認是否應移除或遮罩姓名、生日、Email、工作、家庭背景與完整答案。若接任方只需要維護程式，不需要測試資料，可只提供少量去識別化 fixture，而不提供 production dump。

## 物件儲存

品牌圖片與結果相關媒體使用 S3 相容儲存。交接時應提供 bucket/project 識別、region、object key 規則、CORS、讀寫 policy、presigned URL／storage proxy 設定與 lifecycle policy。實際 access key 應使用新建立且受限的 service account，不能分享 root key。
